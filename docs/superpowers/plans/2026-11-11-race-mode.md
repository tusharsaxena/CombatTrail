# Ka0s Combat Trail Race mode (DPS Race merged in): implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: superpowers:subagent-driven-development. Steps use checkbox
> (`- [ ]`) syntax. **This run executes milestone by milestone through Workflow scripts** (owner: "use ultracode
> to spawn dynamic workflows"): one implementer agent per task, then an adversarial reviewer per task, then the
> gate. Tasks inside a milestone that touch disjoint files may run in parallel; the ledger says which.

**Goal:** Retire DPS Race as an addon and rebuild every one of its features as **Race mode** inside Combat
Trail, Retail only, so that a race is a Combat Trail fight that happens to be timed.

**Architecture:** Combat Trail's fight pipeline stays the owner of the meter session (`Fight` → `Recorder` →
`Bests`/`Results`). A new race layer rides on it: `Race` arms, watches `FIGHT_STARTED` for the first hit on a
dummy, runs the buzzer, and hands the fight a `race` part that `Recorder` saves. Everything race-specific on
screen lives in a new **Race window** drawn with the HUD's own style helpers. Results and a new Insights tab
read races as fight records that carry a `race` part.

**Tech stack:** unchanged. Lua 5.1 (WoW), Ace3, LibKa0s v1.94.0 vendored, headless suites under both kit
profiles, luacheck, lizard.

**Spec:** `docs/superpowers/specs/2026-11-11-race-mode-design.md` ("the spec"). Also read the v0.1.0 design
`docs/superpowers/specs/2026-11-10-combat-trail-design.md` ("the CT spec").

**Source of ported code:** DpsRace `master` at **f8078c7**, checked out at `../DpsRace`. Read it, never write
to it until Task F2. "DR `X.lua`" below means `../DpsRace/modules/X.lua` at that commit.

**Inputs every implementer reads first:** the spec; `CLAUDE.md`; `docs/ARCHITECTURE.md`; the recon file
`docs/superpowers/plans/2026-11-11-race-mode-recon.md` (Task R0's output; cite it as `R:<area>#<item>`);
the DR files the task names; the CT files the task modifies.

## Global constraints

- The Ka0s WoW Addon Standard as `CLAUDE.md` states it. A change that would deviate STOPS and is reported to the
  owner, never done silently; an accepted deviation is a row in `docs/ARCHITECTURE.md` → `## Documented
  deviations`.
- **Green gate before every commit:** `lua tests/run.lua`, `KA0S_KIT_CLIENT=forever lua tests/run.lua`,
  `~/.claude/dev-copilot/bin/ka0s-bounded luacheck .` (0/0), and
  `~/.claude/dev-copilot/bin/ka0s-bounded lizard -C 15 -x "./libs/*" -x "./tests/_kit/*" .` with no warning.
  `docs/test-cases.md` is regenerated with `lua tests/run.lua --list > docs/test-cases.md`, and the README badge
  equals its Total row.
- **Line endings:** every tracked file is CRLF (`.gitattributes`). A write from a script or `Write` leaves LF;
  convert before committing (the `eol` kit suite fails otherwise).
- **Never edit** `libs/` or `tests/_kit/`. LibKa0s needs are filed as issues on LibKa0s.
- **Layout cap 1500 lines per file, CCN 15.** New race code goes into new files. `Hud.lua` (1070),
  `Results_Table.lua` (1197), `Results_Fights.lua` (1009) and `Results.lua` (984) take seams only.
- **Retail only:** every race control, page, verb, binding, launcher entry and filter is declared through
  `NS.Compat.ForClient({ "retail" })` and is **absent** on Forever, with a present test on Retail and an absent
  test on Forever (clients-§4, clients-§6). Training dummies (A2) are on both clients.
- **Secret values:** race code copies live meter values into C-side widgets only; scoring, flags and bests read
  plain values after combat. Nothing secret enters SavedVariables. Follow `docs/midnight-quirks.md`.
- **Words** (spec §8): "Race mode", "race", "Race window"; everything else in Combat Trail's vocabulary (fight,
  history, Results). No "run" or "DPS Race" in user-facing strings except the Race mode page's one-line history
  note.
- **No version bump**, no tag, no release. No commit to `main`. Never auto-push except at milestone checkpoints.
- Recording defaults (spec §3, owner): minimum length **30 s Retail, 15 s Forever**; content toggles all on,
  scenarios included. Race boards (spec §5, owner): **character + spec + dummy kind + length**.

## Review focus

Inputs no task's happy path covers, most likely to bite first. Each has its pinning test in the owning task.

1. **A race armed, then the player pulls something that is not a dummy** (a mob walks into them, or they enter an
   instance). Expected: the arm cancels, the pull is a normal fight, no race part, no error. Test in B1.
2. **Arm, then `/reload` before the first hit.** Expected: no ghost race. The arm is dropped (DR's rule) and the
   Race window comes back idle. Test in B2.
3. **Saved races exist while Race mode is off, or the profile changes, or the client is Forever** (shared
   account-wide history). Expected: Results and Insights list them as fights with their race DPS, with no race
   controls on Forever and no Lua error. Test in D1 (both kit profiles).
4. **Attached Race window while the HUD is hidden** (HUD visibility "toggle", or closed by hand). Expected: the
   Race window still shows where the attached HUD would stand, never at 0,0 or off screen. Test in C1.
5. **A race on a dummy the meter already holds a session for (`sharedSession`), or two pulls inside the restart
   gap.** Expected: flagged, the score netted against the arm baseline, saved once. Test in B1.
