# Automated tests — Ka0s Combat Trail

The record of the four out-of-game suites (automated-tests). Each run is one frozen, dated bundle
under `docs/automated-tests/<YYYYMMDD-HHMMSS>/`, stamped in local time, and `RESULTS.md` holds one
row per run, overwritten in place so its git history is the trend line.

## Producing a run

From the repo root:

```sh
bash tests/_kit/run-automated-tests.sh                        # all four suites, writes a bundle
bash tests/_kit/run-automated-tests.sh --no-bundle            # print only, write nothing
bash tests/_kit/run-automated-tests.sh --release 0.1.0        # a release record; refused on a dirty tree
```

The runner is the vendored kit's and is never edited here. It writes, per bundle, `manifest.json`
(every suite's status and counts), `lint.txt`, `tests.txt`, `test-cases.md`, `perf.txt` and
`perf.json` when the perf suite ran, `complexity.txt`, and `ANALYSIS.md`, the write-up
(`/dev-copilot:wow-automated-tests` writes it after the run).

## The suites

| Suite | What it runs | Gates the commit? | Gates the release (tag)? |
|---|---|---|---|
| `lint` | `luacheck .` | yes | yes |
| `tests` | `lua tests/run.lua` | yes | yes |
| `perf` | `lua tests/perf.lua` (absent today, so recorded as a skip) | no, recorded only | yes, at `pass`; a skip is not evaluated |
| `complexity` | `lizard` over the kit's sighted shadow | no, recorded only | yes, at `pass` with zero functions above CCN 15 |

A missing tool is a skip, not a failure. `RESULTS.md` is generated by the runner and never
hand-edited, apart from the watch list's `Disposition` column (automated-tests-§4). Bundles are never
pruned.
